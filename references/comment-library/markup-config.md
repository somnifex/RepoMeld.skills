# 标记 / 配置 / 数据语言范本（加载条件：`.html` `.css` `.scss` `.sql` `.yaml` `.toml` `.ini` `.properties` `.env` `Dockerfile` 等）

**总原则：配置与标记文件里的注释往往是"为什么是这个值"的唯一记录，默认保守。** 只有明显的流程残留（agent 叙事、临时标记）才动；语义/生成标记无条件保留。

## HTML

- `<!-- ⟨...⟩ -->`；注释掉的标记块 = 残留 → 删除（VCS 承载历史）。删除前确认没有模板引擎条件逻辑依赖注释体。
- 条件注释 `<!--[if IE]> ... <![endif]-->`：仅旧代码存在 → 默认保留，存疑 escalate。
- 模板引擎变体：Jinja2 `{# ⟨...⟩ #}`；ERB `<%# ⟨...⟩ %>`；Thymeleaf `<!--/* ⟨...⟩ */-->`（解析时移除的 Thymeleaf 专用注释）；Vue SFC 用 `<!-- -->`。

## CSS / SCSS

- CSS 只有 `/* */`（不可嵌套）；SCSS/Less 的 `//` 不进产物，`/* */` 进产物。
- **`/*! ... */` important 注释：minifier 压缩时会被保留——惯例用于许可证头 → 绝对禁删。**
```css
/*! ⟨library name ⟨version⟩ | ⟨license⟩ | ⟨homepage⟩ */
```
- 段落组织（Section banner，如 `/* ===== Buttons ===== */`）：统一、简化属低风险 L1；位置标记无信息量时可删。
- KSS 文档注释（`// ⟨Component⟩` + `// Styleguide ⟨1.1⟩`）：有 KSS 构建的仓库属承重 → 保留。

## SQL

- `-- ⟨...⟩`（MySQL 要求第二个 `-` 后至少一个空白/控制字符）；`/* ⟨...⟩ */` 多行。
- **MySQL 可执行注释（承重）**：
  - `/*! ⟨MySQL-specific code⟩ */`：MySQL 会**解析执行**内容；
  - 版本化：`/*!50110 ⟨...⟩ */`——服务器版本 ≥ 5.01.10 才执行（格式：主版本两位 + 次两位 + release 两位）；
  - 优化器 hint：`/*+ ⟨hint⟩ */`，**hint 会存储在对象定义里**。
  - mysqldump 产物中的这些注释删除 = 语义/兼容性丢失 → 生成产物不动。
- 迁移文件头部注释（这次迁移为什么存在）：保留——它承载历史与回滚依据。

## YAML / TOML / INI / properties / .env

- 注释符：YAML / TOML / `.env` / INI 用 `#`；Java properties 另有 `!`。
- K8s / Helm 等清单文件：注释记录调参意图与依赖关系 → 保留；生成标记（`# Generated by ⟨X⟩. DO NOT EDIT.`、`# Code generated by ...`）→ 禁删。
- 值级注释范本（仅当需要重写时套用）：
```yaml
# ⟨timeout_seconds⟩ — ⟨why this value / constraint / ticket⟩
⟨key⟩: ⟨value⟩
```

## Dockerfile

- `# ⟨...⟩` 注释。
- **`# syntax=docker/dockerfile:1` 是解析器指令，必须是文件第一行 → 禁动**。
- 阶段/层注释（`# ⟨stage purpose⟩`）保留。

## SPDX（跨语言通用）

```text
// SPDX-License-Identifier: MIT                 （C 系语言）
/* SPDX-License-Identifier: MIT OR Apache-2.0 */
# SPDX-License-Identifier: GPL-2.0-or-later     （脚本/配置）
```
- 每文件一行：注释符 + `SPDX-License-Identifier:` + 合法 SPDX 表达式（`AND`/`OR`/`WITH` 组合；GPL 系必须带 `-only`/`-or-later`）。
- 任何文件里的 SPDX 行禁删禁改；官方明确：添加 SPDX ID 时**不得移除或修改既有版权声明**。
