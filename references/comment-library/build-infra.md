# 构建与基础设施文件范本（加载条件：`CMakeLists.txt` `Makefile` `*.mk` `*.tf` `*.hcl` `*.gradle` `BUILD` `*.bzl` `nginx.conf` `httpd.conf` `.gitignore` `.dockerignore` `.editorconfig` 等）

**总原则：构建/基础设施文件里的注释经常直接关联行为或被工具读取；每个文件先过"承重候选"审查，改写默认保守。**

## CMake

### B1 注释语法

```cmake
# ⟨Line comment.⟩
#[[ Bracket comment:
    spans multiple lines; may contain # and unbalanced quotes. ]]
#[==[ Level-two bracket comment; ]] inside is fine. ]==]
```

- 行注释 `#`；括号注释 `#[[ ... ]]`，`=` 数量控制嵌套级别（`#[==[ ... ]==]`）——多行块比连续行注释更不易被参数拆分破坏，仓库已用时保持一致。
- 生成文件标记（`# Generated by ...`）与 `cmake_minimum_required` 上方的说明注释保留。

## Makefile

### B2 注释规则（含陷阱，GNU make 官方行为）

```make
# ⟨Comment outside recipes: stripped by make.⟩
VAR := value      # ⟨Comment after a variable line.⟩

define ⟨BLOCK⟩
# ⟨Preserved in the variable value; only interpreted at expansion.⟩
endef

target:
	@echo running      # ⟨Passed to the SHELL, not stripped by make.⟩
	echo literal \# ok
```

- recipe 行（tab 开头）中的 `#` 连同其后文本**交给 shell**——是否是注释由 shell 决定；recipe 内 tab 开头的独立注释行同样进入 recipe。
- 字面 `#` 用 `\#` 转义；行尾反斜杠会把注释延续到下一行。
- `define` 块内的注释**保留在变量值里**、展开时才解释——改写会改变展开结果，承重候选，默认不动。
- 注释不能出现在变量引用/函数调用内部（那里的 `#` 是字面量）。

## Terraform / HCL

### B3 注释语法

```hcl
# ⟨Primary single-line style.⟩
// ⟨Also accepted.⟩
/* ⟨Multi-line
     comment.⟩ */
resource "⟨aws_s3_bucket⟩" "⟨name⟩" {}
```

- 三种写法 HCL 原生语法都接受；**同一文件保持一种**（默认 `#`）。`terraform fmt` 不重排注释文本。
- 资源上方的"为什么是这个值/这个资源"注释保留（等价于配置语义记录）。

## Nginx

### B4 注释规则

```nginx
# ⟨comment⟩
listen 80;  # ⟨why this port⟩
```

- `#` 到行尾，无块注释。`.conf` 里的注释多为调参依据 → 保留。

## Apache httpd

### B5 注释规则（含陷阱）

```apache
# ⟨comment⟩
Listen 80
```

- 官方规则：注释行以 `#` 开头；**注释不允许出现在指令同一行**（`Listen 80  # port` 会报错）。改写时不得把注释挪到指令行尾。
- 反斜杠续行的注释行整体是注释（续行也被当作注释）。

## .gitignore / .dockerignore

### B6 注释与转义语义（承重候选）

```gitignore
# ⟨Build output⟩
/build/
# Escape literal characters: \#file is a real name, ! negation below
!\#file
```

- `#` 只在**行首**才是注释；`\#` / `\!` 转义字面量；`!` 是否定模式。
- **尾随空格有语义**：模式行的尾随空格默认被剥离，需 `\` 转义保留——不要机械清理这两类文件的行尾空白。
- 存疑用 `git check-ignore -v ⟨path⟩` 验证；不确定 → escalate。

## .editorconfig

### B7 注释规则

- `#` 或 `;` 注释（INI 风格）。

## Gradle / Bazel

### B8 注释规则

- Groovy 与 Kotlin DSL：`//` 与 `/* */`，无文档注释机制，按通用 why 规则处理。
- Bazel `BUILD` / `*.bzl`：`#` 注释；buildifier 抑制指令 `# buildifier: disable=⟨tag⟩` 属工具指令（承重）；BUILD 文件注释解释非显然目标 → 保留。
