# Go 范本（加载条件：`.go`）

## 语法

- `//` 行注释是常态；`/* */` 主要用于包注释或屏蔽大段代码（Effective Go）。
- 紧贴顶层声明上方、无空行间隔的注释 = **doc comment**，godoc / pkg.go.dev 直接渲染。

## 文档注释范本（go.dev/doc/comment 官方规则与示例）

### G1 包注释
```go
// Package ⟨path⟩ implements ⟨utility routines for manipulating slash-separated
// paths.⟩
//
// ⟨Second paragraph: expectations, constraints, cross-references.⟩
package ⟨path⟩
```
- 首句以 `Package ⟨name⟩` 开头；多文件包只在**一个**文件里写（通常 `doc.go`），多个包注释会被拼接。
- 每个包都应有包注释；可执行命令的注释以程序名开头。

### G2 函数
```go
// Quote returns a double-quoted Go string literal representing s.
func Quote(s string) string
```
```go
// HasPrefix reports whether the string s begins with prefix.
func HasPrefix(s, prefix string) bool
```
- **首词 = 被声明的标识符名**，完整句子。
- 布尔函数用 `reports whether`（不写 "or not"）。
- 讲返回什么/做什么，不解释内部算法；可提复杂度与特殊情形。

### G3 类型（含零值语义）
```go
// A Buffer is a variable-sized buffer of bytes with Read and Write methods.
// The zero value for Buffer is an empty buffer ready to use.
type Buffer struct { ... }
```
零值含义、并发安全保证（超出单 goroutine 假设时）必须写。

### G4 弃用
```go
// Package rc4 implements the RC4 stream cipher.
//
// Deprecated: RC4 is cryptographically broken and should not be used
// except for compatibility with legacy systems.
package rc4
```
`Deprecated:` 开头的段落被工具链识别（pkg.go.dev 默认隐藏、linter 告警）；必须给原因与替代方案。这是官方约定的弃用机制（Go 1.19+）。

### G5 TODO / BUG 标记
```go
// TODO(⟨uid⟩): ⟨body⟩
// BUG(⟨uid⟩): ⟨body⟩
```
`MARKER(uid):` 形式会被 pkg.go.dev 收集到专门区块。官方未规定 TODO 格式，stdlib 实际混用 `// TODO(⟨uid⟩)` 与 `// TODO:` 两种形式；规范化沿用仓库既有形式，需挂追踪号时优先 `// TODO: ⟨issue⟩: ⟨what⟩`。

### G6 分节/链接（godoc 富文本）
- 标题：单独一行 `# ⟨Title⟩`，前后空行。
- 链接定义：`[Text]: ⟨URL⟩` 行，正文用 `[Text]` 引用；doc 内互链 `[Name1.Name2]`、`[pkg.Name]`。

### G7 方法
```go
// Read reads up to len(p) bytes into p and returns the number of
// bytes read.
func (r *⟨Reader⟩) Read(⟨p⟩ []byte) (n int, err error)
```
```go
// Push pushes ⟨element⟩ onto the queue and reports whether the queue
// was previously empty.
func (q *⟨Queue⟩) Push(⟨element⟩ ⟨T⟩) bool
```
- 方法注释以**方法名**开头（不以类型名开头）；沿用 G2 的 `reports whether` 约定。
- 接收者名短小（类型小写首字母或惯用缩写），同一类型全仓库一致——接收者命名属代码风格，注释改写不顺手改名。

### G8 列表与代码块（godoc 富文本，缩进是语义）
```go
// ⟨Summary.⟩
//
// Rules:
//   - ⟨first item⟩
//   - ⟨second item⟩
//
// Example:
//
//	⟨example line⟩
```
- 列表行以 `-`/`*`/`+` 或 `数字.` 起始；缩进的注释行渲染为代码块——**缩进与空行是渲染语义**，整块改写时保持结构。
- gofmt 会把列表项缩进统一为 tab；交给 gofmt 即可。

## 行内注释范本

```go
// ⟨why sentence⟩
⟨code⟩
```
gofmt（Go 1.19 起）会规范化 doc comment 的缩进与空行——写成 `// ` 单空格即可，交给 gofmt。

## 承重注释（删除会破坏构建/工具）

| 写法 | 作用 |
|---|---|
| `//go:build ⟨linux⟩` | 构建标签；必须位于 package 子句前且与代码间有空行分隔 |
| `//go:generate ⟨cmd⟩` | `go generate` 的输入 |
| `//go:embed ⟨pattern⟩` | 编译期嵌入资源 |
| `//go:noinline` 等 | 编译器指令 |
| `// Code generated by ⟨X⟩. DO NOT EDIT.` | 生成文件标记；工具链以 `Code generated` 开头识别，手工修改与删除都被禁止 |
| `// Deprecated:` 段落 | 官方弃用机制，保留 |

## 工具约束

- gofmt / goimports：重排 doc comment 格式，模板按其规范书写即可。
- revive / golangci-lint 的 `exported` 规则：导出符号缺 doc comment 会报错。补写用 G1–G4 模板，按代码事实填槽，不写空话。
